# 반딧불이 이슬 모으기

밤이 끝나기 전에 반딧불이가 숲의 이슬방울을 모두 모으는 한 화면 도트 게임입니다. 레벨은 3개이고 레벨마다 이슬방울 수와 제한 시간이 다릅니다.
HTML + Canvas 2D + JavaScript(ES modules)로 만들었고, 의존성과 빌드 도구가 없습니다.

## 배포 주소

https://eunjin-kwon.github.io/dotgame-eunjin/ (GitHub Pages)

사용자와 Claude 계획 세션이 이 주소와 로컬 서버에서 직접 열어 확인했습니다.

## 여는 법

ES module은 `file://`에서 CORS로 막혀 빈 화면이 됩니다. 반드시 로컬 서버로 여세요.

```sh
python3 -m http.server 8000
```

그다음 브라우저에서 http://localhost:8000/index.html 을 엽니다. `index.html`을 파일로 직접 열지 마세요.

## 조작

- 방향키: 반딧불이 이동 (한 번 누르면 한 칸, 누르고 있으면 150 ms마다 한 칸)
- Enter: 타이틀에서 시작, 실패 후 같은 레벨 다시 시작, 클리어 후 다음 레벨로, 최종 화면에서 타이틀로

## 규칙

- 레벨은 3개입니다: 레벨 1은 60초·이슬방울 8개, 레벨 2는 50초·10개, 레벨 3은 45초·12개입니다. 제한 시간은 정수 초 단위로 줄어듭니다.
- 레벨의 이슬방울을 모두 모으면 클리어하고, Enter로 다음 레벨로 갑니다. 레벨 3을 클리어하면 "모두 클리어!" 최종 화면이 나옵니다.
- 거미는 가로로 왕복합니다. 반딧불이와 같은 칸이 되거나 자리를 맞바꾸면 실패합니다. 제한 시간이 0이 되어도 실패합니다.
- 실패하면 같은 레벨이 처음부터 다시 시작하고, 이미 클리어한 레벨의 점수는 유지됩니다.
- 레벨 점수는 이슬방울 1개당 100점 + 클리어 때 남은 정수 초 × 10점이고, 실패한 레벨은 0점입니다. 총점은 세 레벨 점수의 합이며 최종 화면에 나옵니다.
- 효과음 3개(이슬방울, 클리어, 실패)는 Web Audio로 만든 소리이고, 브라우저 정책상 Enter를 처음 누른 뒤에 납니다. 소리를 쓸 수 없어도 게임은 동작합니다.
- 최고 점수는 세 레벨을 모두 클리어한 총점만 브라우저 `localStorage` 키 하나(`dotgame-eunjin-highscore`)에 저장하고, 타이틀과 최종 화면에 보입니다. 저장을 쓸 수 없으면 최고 점수 줄만 숨깁니다.

## 테스트

```sh
node --test
```

이 테스트는 Node 20.20.2와 22.23.5에서 91개 모두 통과하는 것을 확인했습니다. `node --test test/`처럼 폴더를 인자로 주면 Node 21 이상에서는 그 인자를 파일 패턴으로 읽어 실패하므로(`Cannot find module '…/test'`), 인자 없이 `node --test`를 씁니다. 인자 없이 실행하면 `test/` 안의 테스트를 자동으로 찾습니다.

## 현재 상태와 한계

- 레벨은 3개로 고정이며 레벨 4 이상, 랜덤 맵, 에디터는 없습니다. 거미는 모든 레벨에서 1마리입니다.
- 레벨 맵 3개는 `src/levels.js`에 있으며 GAME_DESIGN.md 5장의 문자 규칙을 그대로 씁니다. `#` 벽, `.` 바닥, `P` 반딧불이 시작, `o` 이슬방울, `S` 거미 시작입니다. 레벨을 바꾸려면 이 문자열을 고치면 됩니다.
- 한글 서체 한계: canvas font는 `monospace` 한 가지로 지정했습니다. 한글 글리프는 시스템 대체 글꼴로 그려져 영문·숫자와 모양이 다르게 보입니다. 웹폰트는 쓰지 않습니다. 사용자가 이 상태를 확인하고 인정했습니다.
- 더블클릭: `index.html`을 파일로 열면 빈 화면입니다(위 "여는 법" 참고).
- 품질 게이트(goal 완료 도장)는 통과하지 못했습니다. 구현은 goal-1–5까지 커밋되었고 goal-1–4는 blocked, goal-5는 active 상태입니다. 게이트 시도와 원인은 REPORT.md와 `.gjc/` 아래 기록에 있습니다.
- 제출은 마감(2026-11-13 자정) 이후이며 커밋 시각은 그대로입니다.

## 파일 구성

- `AGENTS.md`: 이 프로젝트에서 에이전트가 따를 규칙(의존성 금지, 기획서 우선, 완료 조건 등)
- `GAME_DESIGN.md`: 기획서. 2장 이동·규칙, 3장 화면 흐름, 4장 오브젝트, 5장 맵(레벨 1–3), 6장 팔레트, 7장 소리·UI 텍스트, 8장 기술 스펙, 9장 수용 기준(1–37), 10장 범위 밖
- `.gjc/`: 작업 기록. 계획(ralplan), goal 원장(ultragoal), 검토 증거. 지우지 마세요
- `src/`: 게임 코드. `logic.js` 순수 규칙, `levels.js` 맵, `render.js` 그리기, `main.js` 입력과 프레임, `sprites.js` 스프라이트와 팔레트, `strings.js` 화면 문구, `audio.js` 효과음, `storage.js` 최고 점수 저장
- `test/`: `node --test`로 실행하는 테스트
- `screenshots/`: 실제 화면 캡처 4장
- `index.html`: 캔버스와 `src/main.js` 로드
