## Summary
R3는 goal 두 개다. goal-4는 레벨 2·3(맵·시간·레벨 전환·레벨 표시, 수용 27~31), goal-5는 효과음·최고 점수 저장·최종 화면(수용 32~37)이다. 착수 게이트는 design-v3 커밋이다: 기획서 v3(5장 레벨 2·3, 7장, 8장, 9장 27~37, 10장 전부)를 에이전트가 쓰고 사람이 맞다/아니다로 확인한 뒤 커밋해야 goal-4를 시작한다. v3는 R2에서 굳은 충돌 문구(9장 수용 24, 2장 60초 고정, 3장 클리어 흐름)도 같이 교체한다. 코드의 숫자는 전부 기획서 v3에서 온다. 각 goal의 완료는 사람이 브라우저에서 수용 기준 번호를 보고 확인했을 때다.

## 1. RALPLAN-DR 요약

### Principles
1. 기획서가 유일한 기준이다. 숫자(60/50/45초, 8/10/12방울, 거미 1마리·300 ms, 점수식)는 기획서 v3에 먼저 쓰고 코드와 테스트는 그 숫자를 복사한다.
2. `src/logic.js`는 순수 함수만 둔다. Web Audio와 `localStorage`처럼 환경을 만지는 코드는 로직 밖(별 모듈 + `main.js` 배선)에 둔다.
3. 맵은 5장 문자 블록을 `src/levels.js`에 그대로 복사한다. 좌표를 손으로 쓰지 않는다.
4. 구조를 늘리지 않는다. 레벨 차이는 맵·시간·방울 수뿐이고 거미는 모든 레벨 1마리다.
5. 완료는 테스트 통과가 아니라 사람이 브라우저에서 본 수용 기준이다. fixture 스크린샷은 증거가 아니다.

### Decision Drivers (top 3)
1. **착수 게이트가 기획서 커밋이다.** goal-4 코드는 design-v3 커밋 전에 시작할 수 없다(AGENTS.md "기획서가 애매하면 먼저 고친다" + 결정 L).
2. **goal당 1회 시도, 최대 40분(결정 K).** 레벨 전환 리팩터링을 크게 벌이면 goal-4가 시간 안에 안 끝난다. 기존 `createWorld`/`enter`/`advance` 모양을 유지하는 최소 변경을 고른다.
3. **goal-5는 버릴 수 있는 goal이다.** 효과음·저장·최종 화면은 goal-4 산출물에 의존하지만 goal-4는 goal-5에 의존하지 않아야 한다. 못 끝내면 버리고 REPORT에 사실대로 적는다.

### Viable Options

**O1. 레벨 진행 상태를 어디에 두는가**
- **O1-A (채택): `logic.js`의 world에 `levelIndex`, `totalScore`를 넣고 `LEVELS` 배열로 전환을 순수 함수(`enter`)가 처리한다.**
  - 장: 전환·점수 누적·실패 재시작이 전부 `node --test`로 검증 가능. `render.js`/`main.js`는 world만 읽는다. 기존 phase 기계에 `final` 하나만 추가.
  - 단: world 모양이 커지고 goal-3 테스트 일부(클리어 후 Enter → 타이틀)를 v3 흐름으로 고쳐야 한다.
- **O1-B: 세션 상태(현재 레벨, 총점)를 `main.js`가 들고 `logic.js`는 레벨 하나만 안다.**
  - 장: `logic.js` 변경이 가장 작다.
  - 단: 전환·점수 누적·실패 시 점수 유지(수용 31)가 DOM 배선 쪽으로 새서 자동 테스트가 `wiring.test.js` 수준으로만 가능. 30~40분 제한에서 디버깅 비용이 더 크다.
- 판단: 수용 27·29·31·33·36이 전부 "상태 전이 + 숫자" 검증이라 순수 함수 쪽이 증거를 싸게 만든다 → O1-A.

**O2. 효과음·최고 점수를 어디에 두는가**
- **O2-A (채택): `src/audio.js`(Web Audio 합성), `src/storage.js`(localStorage 읽기/쓰기) 두 모듈을 만들고 `main.js`가 world phase 변화에 맞춰 호출. 두 모듈은 try/catch로 실패를 삼킨다.**
  - 장: Principle 2 유지. 수용 37(소리·저장 불가 환경)이 모듈 단위로 테스트 가능(주입된 가짜 객체로).
  - 단: 파일 2개 추가 → 8장 모듈 목록에 적어야 한다.
- **O2-B: `render.js`/`main.js` 안에 인라인.**
  - 장: 파일 추가 없음.
  - 단: `render.js`가 사이드이펙트를 갖게 되고(주석에 "never changes state"라고 박혀 있다) 테스트 불가.
- 판단: O2-A.

**O3. 레벨 시간(60/50/45)을 어떻게 싣는가**
- **O3-A (채택): `levels.js`에 `LEVELS = [{ rows, timeLimitS }, …]` 로 두고 `createWorld`가 `level.timeLimitS`를 읽는다. 기존 상수 `TIME_LIMIT_S`는 제거한다(하위 호환 유지 금지).**
- O3-B: `createWorld(level, nowMs, timeLimitS)` 인자 추가 → 호출부마다 숫자를 다시 적게 되어 "숫자는 한 곳" 규칙과 어긋난다.
- 판단: O3-A.

### 대안 무효화 근거 (옵션 1개만 남은 항목)
- **거미 수·속도**: 결정 A절이 모든 레벨 1마리·300 ms로 확정. 레벨별 거미 수 변경·속도 변경 대안은 사람 확정값 변경이라 검토하지 않는다.
- **맵 데이터**: 결정 C·D절 문자 블록이 확정이고 도달 가능성·방울 수 검증이 끝났다(레벨 2·3 = 12행×16열, 방울 10·12개, 거미 S = (7,6)·(5,3), 왕복 구간 x=1~14, P = (4,10)·(2,10)). 맵을 다시 만들거나 손보는 대안 없음.
- **최고 점수 저장 매체**: 결정 F절이 `localStorage` 키 하나 `dotgame-eunjin-highscore`로 확정. 서버·파일·다중 키 대안은 AGENTS.md 금지 사항(서버/DB)과 충돌해 무효.
- **소리 소스**: 결정 E절 + AGENTS.md가 오디오 파일을 금지 → Web Audio 합성만 가능.

## Handoff
- **executor**: 단계 1(design-v3 문서), 단계 2, 단계 3을 각각 별도 슬라이스로. 각 슬라이스에 "변경 파일 + 테스트 계획 + 증거 목록 + 완료 조건(수용 번호)"를 그대로 전달한다. 단계 2·3은 단계 1 커밋 전에 착수 금지.
- **architect**: 단계 2 착수 전, O1-A의 world 필드 추가(`levelIndex`/`totalScore`)와 `enter` 전환이 `logic.js` 순수성·테스트 가능성을 지키는지 읽기 전용 점검(선택, 10분 이내).
- **critic**: design-v3 초안이 사람에게 가기 전 1회, 충돌 항목 7행이 빠짐없이 교체됐는지와 기획서에 없는 기능이 들어갔는지 확인.
- **autoresearch / ultragoal**: 불필요. 외부 조사 대상이 없고(의존성 0, 사람 확정값 고정) 목표가 2 goal로 좁다.
