## RALPLAN-DR summary
모드: short (사전 부검 불필요 — 범위가 기획서로 닫혀 있고 되돌리기 비용이 낮다).

### Principles
1. 기획서가 단일 진실이다. 코드·테스트의 모든 숫자는 GAME_DESIGN.md에서 온다. 기획서에 없는 것은 만들지 않는다.
2. 규칙과 **규칙의 순서**는 둘 다 순수 함수 안에 있다. 테스트 밖(main.js)에 순서 버그가 남지 않게 한다.
3. 시계는 하나다. 모든 시간 규칙은 프레임 콜백이 준 `nowMs` 하나로 계산한다.
4. 완료는 테스트 통과가 아니라 9장 수용 기준 번호로 사람이 브라우저에서 확인하는 것이다.
5. 미결정 사항은 추측해서 코드에 넣지 않고 Intent Reconciliation에 기본 제안과 함께 올린다.

### Decision Drivers (top 3)
1. **게이트 순서**: design-v2 커밋 전에는 코드를 고치지 않는다. 기획서가 흔들리면 테스트 기대값이 모두 흔들린다.
2. **테스트 가능성**: 순찰·접촉·타이머·점수·화면 전이와 그것들의 **실행 순서**가 전부 node --test로 고정되어야 한다.
3. **값 보존**: 8개 / 300 ms / 60 s / 100점 / 10점 / 16×12 / 32 px / 8색은 사람이 결정한 값이며 코드가 바꿀 수 없다.

### Viable Options (아키텍처)
**옵션 B (채택, architect 권고) — `createWorld` + 단일 `advance`**
- 장점: 틱 순서·동시 사건 우선순위·phase 전이·리셋이 한 고정에 모인다. goal-3에서 재작업이 없다(phase 값만 추가). 시계가 자연히 하나로 정리된다.
- 단점: S2가 pass 1 산정보다 조금 크다. 기존 `requestMove` 호출부가 `advance` 안으로 들어가며 wiring 테스트를 건드려야 한다.

**옵션 A (기각) — 규칙 함수 여러 개를 main.js가 순서대로 호출 (pass 1 원안)**
- 장점: S2를 작게 자른다.
- 기각 근거: 순서 규칙(O2·O3 동시 틱 우선순위)가 테스트 불가 영역인 main.js에 남는다. Decision Driver 2 위반.

**옵션 C (기각) — keydown에서 즉시 이동(현행 코드)**
- 장점: 입력 지연 0.
- 기각 근거: `performance.now()`와 rAF `nowMs` 두 시계가 섮여 거미 300 ms·타이머 1초 간격을 결정적으로 테스트할 수 없다. 접촉·수집을 두 곳에서 불러야 한다.

**실행 순서 옵션**

## 아키텍처 결정 (상위 결정, pass 2에서 확정)
### 상태와 파이프라인
- `createWorld(level)` → 새 world. 매번 새 객체를 만들고 공유 가변 배열을 반환하지 않는다.
- `world` 필드(에이전트 제안 이름): `phase`, `player{x,y,lockedUntil}`, `spider{x,y,dir,nextStepAt}`, `dewdrops`(남은 칸 집합), `collected`, `timeLeft`(정수 초), `nextSecondAt`, `startedAt`, `reason`(`null` | `'spider'` | `'timeout'`).
- `world.phase` 열거형: goal-2에서 `play | won | lost`, goal-3에서 `title | play | won | lost` (값만 추가, 파이프라인은 그대로).
- `advance(world, nowMs, input)` → 새 world. **유일한 규칙 진입점**. `input`은 goal-2에서 `{ dir }`, goal-3에서 `{ dir, enter }`.
- `main.js`는 (1) keydown/keyup으로 누른 키 목록만 갱신하고, (2) 프레임마다 `advance(world, nowMs, input)`를 한 번 부르고, (3) 그린다. 그 외 규칙을 가지지 않는다.
- **시계는 프레임 `nowMs` 하나만 쓴다. keydown 핸들러에서 `performance.now()`를 호출하지 않는다** (F1/AR-01). 거미 300 ms와 타이머 1전부 같은 시계다. 따라서 선행 항목 F6(rAF·performance.now 혼용)는 **범위 안**이며 goal-2 S4에서 해소된다.
  - 부수 효과: 탭(한 프레임 안에 누르고 떼기)도 한 칸 움직여야 한다(수용 2). 따라서 누른 키 목록은 keyup에서 바로 지우되, **그 프레임에서 아직 소비되지 않은 마지막 누름은 1회 대기열로 남긴다**(에이전트 제안, R1 수용 2·4·5 보존용). 테스트 W3으로 고정.
- `requestMove`, `pressDirection`, `releaseDirection`, `activeDirection`, `MOVE_LOCK_MS`는 그대로 남기고 `advance`가 내부에서 쓴다(R1 테스트 보존).
- `src/logic.js` 본문과 **주석**에 `canvas`, `document`, `window` 문자열을 쓰지 않는다(logic.test.js V-6이 소스 문자열을 검사한다, AR-09).

### 한 틱 순서 (F7 / AR-02 — 확정)
`advance`는 `phase === 'play'`일 때만 아래를 수행한다. 중간에 phase가 바뀜면 **즉시 반환**한다.
1. **플레이어 이동** (`requestMove`, 150 ms 잠금 규칙 그대로)
2. **접촉 검사** → 같은 칸이면 `phase='lost'`, `reason='spider'`, 반환
3. **수집** → 현재 칸에 방울이 있으면 제거하고 `collected += 1`. `collected === 8`이면 `phase='won'`, 반환
4. **거미 이동** (`nowMs >= nextStepAt`일 때 한 칸)
5. **접촉 검사** → 같은 칸이면 `phase='lost'`, `reason='spider'`, 반환
6. **타이머** → `phase === 'play'`일 때만 1초 감소. `timeLeft === 0`이면 `phase='lost'`, `reason='timeout'`
- 한 칸 이동마다 검사하므로 **인접 맞바꿈은 2단계 또는 5단계에서 같은 칸으로 잡힌다**. 따라서 `isContact(player, spider)` — **이전 좌표 인자는 두지 않는다**(F7/AR-05).
- 이 순서가 곴 규칙도 결정한다: 수집과 접촉이 같은 틱이면 2단계가 먼저 → **실패**(O3, D절 명시). 마지막 방울과 시간 0이 같은 틱이면 3단계가 먼저 → **클리어**(O2).

### 타이머 모델 (F6 / AR-03 — 확정)
- `timeLeft`는 **정수 초** 하나만 저장한다. ms 누적값을 따로 두지 않는다.
- 플레이 시작 시 `timeLeft = 60`(사람 결정 H절), `nextSecondAt = startedAt + 1000`.
- `nowMs >= nextSecondAt`이고 `phase === 'play'`일 때 `timeLeft -= 1`, `nextSecondAt += 1000`. 한 프레임에 최대 한 번 감소하고, 지연이 1000 ms를 넘으면 `nextSecondAt`을 `nowMs + 1000`으로 재기준한다(거미와 같은 규칙, AR-04).
- `timeLeft`는 음수로 내려가지 않는다. 0이 된 그 틱에 `lost`/`timeout`.
- 그러므로 **남은 시간은 항상 정수이고, D절의 "1초(내림)"은 이 설계에서 아무것도 바꾸지 않는 무효 조항**이다. 점수 식은 `collected*100 + timeLeft*10`이고 `Math.floor`는 불필요하다. 표시도 같은 정수를 쓴다(O6).
- 표시와 점수가 같은 값에서 오므로 HUD에 보인 숫자와 클리어 점수가 항상 일치한다.

### 거미 이동 간격 (AR-04 — 확정)
- `nextStepAt = startedAt + 300`으로 시작. `nowMs >= nextStepAt`이면 **한 호출에 한 칸**만 움직이고 `nextStepAt += 300`.
- 지연이 한 주기(300 ms)를 넘어 `nowMs >= nextStepAt + 300`이면 쌓인 스텝을 몰아서 움직이지 않고 `nextStepAt = nowMs + 300`으로 **재기준**한다(탭 전환·저사양 프레임에서 순간이동 방지).
- 다음 칸이 벽이면 `dir`를 반전하고 그 틱에 반대 방향으로 한 칸 움직인다.

## goal-2 (목표물·위협·타이머) — 수용 기준 6~17
**완료 조건 (R2_decisions G절, 원문 그대로):**
> index.html을 http로 열어 플레이하면 이슬방울 8개를 먹을 때마다 사라지고 개수가 올라가며, 거미가 가로로 왕복하고, 시간이 60에서 줄어들고, 거미에 닿거나 0이 되면 게임이 멈춘다. (수용 기준 6~17)

### 시작 시점 (F5 / AR-13)
- **goal-2는 페이지 로드 시점에 `phase='play'`로 시작한다.** 첫 프레임의 `nowMs`가 `startedAt`이고 거미와 타이머도 그때 기준이 잡힙다.
- **goal-3에서 이 규칙이 한 번 바뀐다**: 초기 phase가 `title`이 되고, `startedAt`은 Enter로 `play`에 들어간 프레임의 `nowMs`가 된다. `advance`의 틱 순서와 거미·타이머 규칙은 그대로다.

### 규칙 (전부 기획서 값)
- 이슬방울 8개(사람 결정 H절). 방울 칸에 들어가면 사라지고 `collected += 1`. 이미 먹은 칸·빈 칸은 변화 없음(수용 9~11). **방울당 정확히 1회만 증가**한다.
- 거미 1마리, 가로 왕복, 300 ms마다 한 칸(사람 결정 H절), 다음 칸이 벽이면 반전, 처음 방향 왼쪽. 이슬방울을 먹지 않고 방울은 거미를 막지 않는다(수용 12·13). 간격 규칙은 위 AR-04 절.
- 접촉 = 같은 칸. 한 칸 이동마다 검사하므로 맞바꿈도 잡힌다(수용 14·15). 잡히면 `phase='lost'`, `reason='spider'`.
- 제한 시간 60초(사람 결정 H절), 정수 1초씩 감소, 0이면 `phase='lost'`, `reason='timeout'`(수용 16·17).
- 이슬방울 8개를 다 먹으면 goal-2 단계에서도 `phase='won'`으로 멈춘다(AR-06). 화면은 goal-3에서 붙인다.
- **정지 후 규칙 (F4)**: `phase !== 'play'`이면 `advance`는 아무것도 바꾸지 않는다. 즉 **플레이어도 거미도 움직이지 않고 타이머도 줄지 않으며 방향키 입력은 무시된다.** D절 "끝난 뒤" 행을 goal-2부터 적용한다.
- 모든 규칙은 `src/logic.js`의 순수 함수. 캔버스·DOM 접근 없음, 시간은 `nowMs` 인자.

## goal-3 (승패와 화면 전환) — 수용 기준 18~26
**완료 조건 (R2_decisions G절, 원문 그대로):**
> 타이틀에서 Enter로 시작해 모두 모으면 점수가 있는 클리어 화면이, 거미에게 잡히거나 시간이 다 되면 이유가 있는 실패 화면이 뜨고, Enter로 다시 하거나 타이틀로 돌아간다. (수용 기준 18~26)

### 규칙
- `world.phase` 값 하나를 더한다: `title`. 화면은 `title | play | won | lost` 네 가지이고 `won`=클리어, `lost`=실패 화면이다. 새 상태 기계를 따로 만들지 않는다(AR-07).
- **타이틀 입력 규칙 (F5)**: `title`에서는 방향키를 무시하고 타이머·거미가 움직이지 않으며 맵과 반딧불이를 그리지 않고 문구만 보인다(O8). Enter만 `play`로 보낸다(수용 18).
- 클리어: `collected === 8`일 때(수용 19). "클리어!" + 점수(수용 20).
- 점수 = `collected * 100 + timeLeft * 10`. `timeLeft`가 정수이므로 별도 내림 연산은 없다. 실패는 0점(사람 결정 H절).
- 실패 이유는 `world.reason`에서 온다: `'spider'` → "거미에게 잡혔어요", `'timeout'` → "밤이 끝났어요"(수용 21·22).
- `lost`에서 Enter → **`createWorld(level)`로 완전 리셋**: 플레이어 P, 거미 S(왼쪽), 이동 잠금 해제, `timeLeft=60`, 방울 8개 복원, `nextStepAt`·`nextSecondAt` 재기준, 그리고 **main.js의 누른 키 목록을 비운다**(AR-08). 수용 23.
- `won`에서 Enter → `title`(수용 24).
- `won`·`lost`에서 방향키 무시(수용 25, goal-2의 정지 후 규칙과 같은 코드 경로).
- 모든 화면 글자는 같은 `monospace` 패밀리(수용 26).
- **모든 UI 문구는 `src/strings.js` 한 곳에만 둔다.**

## Escalation / Risk Gate
- **실행 정책 (사용자 합의)**: 품질 게이트는 goal당 **1회만** 시도(리뷰 1회 → 그 해시로 체크포인트 1회). 실패해도 반복하지 않고 사실대로 기록한 뒤 다음 goal로 간다.
- **이 계획의 리뷰 반복**: 최대 2회. **이번이 pass 2이므로 리뷰는 바뀜 것만 본다**(F1~F10, AR-01~AR-15 해소 여부). 새 주제는 열지 않는다.
- **중단 기준**: 한 goal에서 같은 시도를 6번 넘게 반복하지 않는다(AGENTS.md).
- **에스컬레이션**: 기획서 값과 구현이 충돌하면 기획서를 먼저 고치고 사람에게 보여준다. 사람 확인 없이 숫자를 바꾸지 않는다.
- **승인 경계(critic)**: S0는 F8 반영 후 사람 확인으로 진행 가능. S1~S6은 이 pass 2 계획이 수락된 뒤에만 착수한다.
