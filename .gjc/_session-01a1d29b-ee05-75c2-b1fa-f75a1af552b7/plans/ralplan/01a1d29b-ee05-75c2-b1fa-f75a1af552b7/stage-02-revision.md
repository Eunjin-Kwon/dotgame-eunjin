## Summary

사람이 2장 값 7개와 타이밍 의미를 확정했다. 따라서 R1a(순수 이동 로직 + `node --test test/`)는 이 계획 승인 후 착수할 수 있다. 그러나 **R1a는 2장 단위 계약만 닫는다. R1 goal("맵 위에서 한 칸 움직인다")은 계속 열린 상태다.** 맵(5장)과 팔레트(6장), 오브젝트(4장)가 비어 있어 화면에서 캐릭터가 움직이는 것을 사람이 볼 수 없고, 완료 판정 근거인 9장도 비어 있다. 이 개정판은 리뷰에서 지적된 발명 값(60초)을 제거하고, 로직 경계를 확정하고, 완료 근거를 9장으로 되돌리고, AGENTS.md가 명명하지 않은 경로를 사람 결정 항목으로 올린다.

## 1. 확정된 사람 결정 (재질문 금지)

1. **2장 값 7개 확정:** 격자 한 칸 이동 / 한 칸 150 ms / 타일 32 px / 화면 512×384 px = 16×12 타일 / 방향키 4개, 대각선 없음 / 이동하려는 칸이 벽이거나 화면 밖이면 제자리 / 짧게 누르면 정확히 한 칸, 누르고 있으면 150 ms마다 한 칸, 한 칸 이동이 끝나기 전 입력은 무시.
2. **타이밍 의미 확정:** 입력 시점에 즉시 한 칸 이동하고, 그 후 150 ms 동안 다음 입력을 잠근다(쿨다운). 이동 중 보간/트윈은 없다. 따라서 "한 칸 이동 시간 150 ms"는 모션 길이가 아니라 입력 잠금 길이로 해석한다.
3. **표기 변경은 후속 작업:** 2장의 "(에이전트 제안)"을 "(확정)"으로 바꾸는 GAME_DESIGN.md 편집은 ralplan 중 금지(계획 가드)다. **이 계획 승인 후 별도 `design-v1:` 커밋으로 수행해야 하는 필수 후속 작업**이며, 아직 수행되지 않았다.
4. **착수 게이트:** "2장 값 사람 확정 후 R1a 착수". 2장 값이 확정되었으므로, 이 계획이 승인되면 R1a 착수 가능.

## 2. Principles

1. **기획서가 유일한 근거.** 2장 7개 값과 확정된 타이밍 의미만 쓴다. 기획서에 없는 숫자(타이머, 점수, 이슬방울 개수 등)는 계획에도 코드에도 테스트에도 넣지 않는다.
2. **빈 장은 채우지 않는다.** 4장(오브젝트), 5장(맵), 6장(팔레트), 9장(수용 기준)은 비어 있다. 맵 문자, 레이아웃, 색 hex, 완료 기준을 계획이나 코드가 발명하지 않는다. 기획서를 먼저 고치고 사람에게 보여준다.
3. **완료 근거는 9장이다.** 계획이 쓰는 검증 항목은 2장 계약 확인용이며 goal 완료 선언 근거가 아니다. 9장이 비어 있는 동안 R1 goal은 열린 상태다.
4. **로직은 순수, 데이터는 분리.** `src/logic.js`는 canvas/document/window를 모른다. 문자→통행 가능 변환은 `src/levels.js` 한 곳에만 둔다. 로직은 통행 가능 질의만 받는다.
5. **테스트 기대값은 기획서 숫자에서만.** 150 ms, 16×12 경계는 2장에서 온다. 코드가 하는 일을 베낀 테스트는 쓰지 않는다. 시간은 인자로 주입해 가짜 시간으로 결정적으로 검증한다.

## 3. Decision Drivers (top 3)

1. **2장은 확정, 5·6·4·9장은 공백.** 확정된 계약(이동 규칙)만 코드로 닫을 수 있고, 맵·표현·완료 판정은 사람 입력 대기다. 이것이 R1a/R1b 분리의 유일한 이유다.
2. **AGENTS.md 완료 조건이 9장을 지목한다.** 9장이 비어 있으므로 어떤 코드 작업도 R1 goal을 공식적으로 닫을 수 없다. 계획은 완료 기준을 만들지 않고 이 공백을 블로커로 올린다.
3. **AGENTS.md가 명명한 파일 집합이 제한적이다.** `src/logic.js`, `src/levels.js`, `src/sprites.js`, `src/strings.js`, `index.html`, 명령 `node --test test/`. 렌더 전용 파일과 테스트 파일명은 명명되지 않았으므로 사람 결정 없이 신설하지 않는다.

## 4. Viable Options

### Option A (권장) — R1a 선행 슬라이스 + R1b 차단 유지
- 내용: 확정된 2장 계약을 `src/logic.js` + `node --test test/`로 닫는다. 맵·스프라이트·렌더·`index.html`은 4·5·6장 확정 후.
- 장점: 발명 0. 확정된 값만 코드화. 가짜 시간 주입으로 결정적 검증. 5·6장 확정 시 로직 변경 없이 데이터만 끼운다.
- 단점: R1a만으로는 사람이 브라우저에서 볼 화면이 없다. goal이 닫히지 않고, 커밋 단위가 `goal-1` 부분 작업이 된다.

### Option B — 4·5·6장 확정까지 R1 전체 보류
- 내용: 코드 작업을 전혀 시작하지 않고, 사람이 4·5·6·9장을 채운 뒤 R1을 한 번에 구현·커밋한다.
- 장점: `goal-1` 커밋 하나로 goal이 완결되고 사람 브라우저 확인까지 한 번에 끝난다. 부분 완료 오인 위험 0.
- 단점: 확정된 2장 계약을 코드로 고정할 기회를 미룬다. 사람 응답까지 진척 0.

### Option C (무효) — 임시 맵 문자/임시 색으로 R1 전체 구현
- 무효 사유: AGENTS.md "기획서에 없는 기능을 만들지 않는다", "색은 6장 8색 hex만", "맵은 5장 문자 규칙을 그대로 복사"를 정면 위반. 또한 fixture 데이터 스크린샷은 증거가 아니라고 명시되어 사람 확인 증거로도 쓸 수 없다. 사용자 요청("기획서에 없는 것은 계획에 넣지 마라")에도 반한다.

**권고: Option A.** R1a는 선행 슬라이스임을 명시하고, R1b는 블로커 해소 전까지 착수하지 않는다. 사람이 "goal 하나 = 커밋 하나"를 더 중시하면 Option B로 전환한다(계획 변경 불필요, R1a만 보류).

## 6. R1 작업 분해 (파일 단위, 기획서 장 연결)

### R1a — 이 계획 승인 후 착수 가능

| 파일 | 작업 | 근거 장 | 내용 |
|------|------|---------|------|
| `src/logic.js` (AGENTS.md 명명) | 생성 | 2장 | 순수 함수만. canvas/document/window 참조 금지. 단일 export: `requestMove(state, dir, nowMs, grid)` → 새 state. 규칙: (a) `nowMs < state.lockedUntil`이면 입력 무시하고 state를 그대로(동등하게) 반환 — 2장 "이동이 끝나기 전 입력 무시". (b) `dir`은 `up`/`down`/`left`/`right` 4개만. 그 외 값과 대각선 조합은 이동 없음 — 2장 "방향키 4개, 대각선 없음". (c) 대상 칸이 `0 <= x < grid.width`, `0 <= y < grid.height` 밖이거나 `grid.blocked(x, y)`가 true면 좌표 불변(제자리) — 2장 "벽과 화면 밖". 이때 잠금 갱신 여부는 (d)와 함께 테스트로 고정한다. | 테스트 (`node --test test/`로 실행; 파일명은 §7-5 경로 결정 대기) | 생성 | 2장 | 150 ms와 16×12를 파일 상단 상수 한 곳에 모으고 출처를 2장으로 주석. 케이스: 4방향 각 1칸 이동 / 대각선·미정의 dir 거부 / 경계 x=0, x=15, y=0, y=11에서 밖으로 향한 입력 시 좌표 불변 / `blocked` true 칸으로 향한 입력 시 좌표 불변 / 잠금 중(nowMs < lockedUntil) 입력 무시 / 잠금 만료 후(nowMs >= lockedUntil) 연속 이동 / `src/logic.js` 텍스트에 `canvas`, `document`, `window` 토큰 없음. |

## 7. R1 검증 항목 (기획서 장 번호 대응)

> **중요 (F-04 / CR-R1-01 / CR-R1-03):** 아래 항목은 **2장 이동 계약을 확인하는 검증 항목이며 goal 완료 기준이 아니다.** AGENTS.md는 완료 조건을 GAME_DESIGN.md 9장으로 정의하고 9장은 비어 있다. 계획은 9장을 대신 쓰지 않는다. R1a가 V-1..V-6을 모두 통과해도 **R1 goal은 열린 상태**이며, 완료 선언에는 사람이 9장에 쓴 R1 수용 기준과 브라우저 확인이 필요하다.

### R1a 검증 — `node --test test/`로 확인 가능 (2장 계약)

- **V-1 (2장: 격자 한 칸 단위)** `up`/`down`/`left`/`right` 각 1회 입력에 좌표가 정확히 1칸만 바뀐다.
- **V-2 (2장: 방향키 4개, 대각선 없음)** 정의되지 않은 dir과 대각선 의도 입력은 좌표를 바꾸지 않는다.
- **V-3 (2장: 화면 밖이면 제자리)** 16×12 그리드 경계(x=0, x=15, y=0, y=11)에서 밖으로 향한 입력은 좌표를 바꾸지 않는다.
- **V-4 (2장: 벽이면 제자리)** `grid.blocked(x, y)`가 true인 칸으로 향한 입력은 좌표를 바꾸지 않는다. (fixture `blocked` 질의, 벽 문자 없음)
- **V-5 (2장: 150 ms, 이동 중 입력 무시)** 이동 직후 `lockedUntil`이 `nowMs + 150`이고, `nowMs < lockedUntil`인 입력은 무시되며, `nowMs >= lockedUntil`인 다음 입력은 1칸 이동을 만든다. 실제 타이머 대기 없이 `nowMs` 주입으로 검증한다.
- **V-6 (AGENTS.md: logic.js는 canvas를 모른다)** 테스트가 `src/logic.js` 파일을 텍스트로 읽어 `canvas`, `document`, `window` 토큰이 등장하지 않음을 assert한다 (CR-R1-04 반영: 수동 "소스 확인"이 아니라 테스트 1개로 고정).

### R1b 검증 — 조건부, 현재 차단 (R1a 결과에 포함하지 않는다)

- **V-7 (2장: 화면 512×384, 타일 32 px) — 5·6장 확정 후.** 관찰 절차: `index.html`을 브라우저로 직접 연다(서버 없음; 필요 시 `python3 -m http.server 8000`). 개발자 도구에서 canvas 요소의 `width`=512, `height`=384를 확인하고, 화면이 16×12 타일 격자로 구성됨을 확인한다.
- **V-8 (5장: 레벨 1 맵) — 5장 확정 후 차단 해제.** 5장 문자 그림과 화면을 나란히 두고, 벽 칸과 빈 칸 배치가 문자 그림과 일치함을 확인한다.
- **V-9 (2장: 한 칸 이동) — 5·6장 확정 후.** 관찰 절차: (1) 반딧불이의 시작 칸 좌표를 격자 기준으로 적는다. (2) → 키를 한 번 짧게 누른다. (3) 반딧불이가 오른쪽으로 정확히 1칸(32 px) 이동한 뒤 멈춘다. (4) ←, ↑, ↓도 같은 방식으로 각 1회 확인한다. (5) 벽에 인접한 칸과 화면 가장자리 칸에서 벽/밖 방향 키를 누르면 칸이 바뀌지 않는다. (6) 키를 계속 누르고 있으면 멈추지 않고 연속으로 칸을 옮긴다. "눈에 보이게" 같은 주관 표현은 쓰지 않고 시작 칸 대비 칸 수 변화로 판정한다.
- **V-10 (6장: 8색 hex) — 6장 공백으로 현재 검증 불가 (차단).** 6장 8색이 확정되면 소스의 색 리터럴이 그 8개 집합 안에 있는지 확인한다.

## 8. Blockers / Open items (사람 결정 필요)

1. **5장 맵 — 비어 있음 (차단).** 맵 문자 규칙(어떤 문자가 벽/빈 칸/시작 위치인지)과 레벨 1의 16×12 문자 그림이 없다. AGENTS.md는 5장 문자 규칙을 `src/levels.js`에 **그대로 복사**하라 하고 좌표 별도 기재를 금지한다. **따라서 R1의 맵 내용은 5장 없이 완성할 수 없다.** 계획은 이 값을 발명하지 않는다.
2. **6장 팔레트 — 비어 있음 (차단).** 8색 hex가 없으면 `src/sprites.js` 팔레트 인덱스의 의미와 렌더 색이 정의되지 않는다. 임시 색 사용은 금지다.
3. **9장 수용 기준 — 비어 있음, R2 소관 (차단).** R1의 공식 완료 판정 근거가 없다. 9장 없이 **R1에서 확인 가능한 것**: 2장 이동 계약 6개(V-1..V-6) 전부를 `node --test test/`로 숫자 기반 검증. 9장 없이 **확인 불가능한 것**: goal 완료 선언, 성공/실패 판정, 점수, 타이머, 레벨 전환 등 R1 범위 밖 항목, 그리고 "R1이 끝났다"는 공식 판정. 계획은 임시 수용 기준을 만들어 완료 근거로 삼지 않는다. 사람이 9장에 R1 항목을 써야 goal을 닫을 수 있다.
4. **4장 오브젝트 — 비어 있음 (차단).** 반딧불이 스프라이트 모양·크기가 정의되지 않아 R1b 렌더에 필요하다.
5. **파일 경로 허용 결정 (열림, F-06 / CR-R1-06).** AGENTS.md가 명명한 파일은 `src/logic.js`, `src/levels.js`, `src/sprites.js`, `src/strings.js`, `index.html`이고 명령은 `node --test test/`다. 계획이 앞서 쓴 `src/render.js`와 `test/logic.test.js`는 **명명되어 있지 않다.** 사람이 (a) 렌더 코드를 명명된 파일 안에 넣을지 아니면 `src/render.js`를 AGENTS.md에 추가할지, (b) 테스트 파일명을 무엇으로 할지 결정해야 한다. 이 계획은 두 경로를 가정하지 않고, `src/logic.js`와 `node --test test/`만 확정으로 쓴다.
6. **타이머 — 기획서 미정의 (F-01).** 제한 시간은 GAME_DESIGN.md 어디에도 숫자가 없다. 이전 계획의 "60초"는 발명 값이므로 삭제했다. R1 범위 밖이며, 필요해지면 사람이 기획서에 먼저 쓴다.
7. **2장 표기 변경 — 필수 후속 작업 (미수행).** "(에이전트 제안)" → "(확정)" 변경은 ralplan 계획 가드로 지금 수행할 수 없다. 이 계획 승인 후 `design-v1:` 커밋으로 반영해야 하며, 현재 기획서에는 여전히 "(에이전트 제안)"으로 적혀 있다.

## 11. Verification Plan

- 명령: `node --test test/` (AGENTS.md 명령어 절). 다른 러너·플래그·의존성 추가 금지.

## 12. Escalation / Risk Gate

- **즉시 에스컬레이션:** 구현 중 4·5·6·9장 값을 추측하고 싶어지는 순간 멈추고 사람에게 묻는다. 같은 시도 6회 초과 금지(AGENTS.md).
- **게이트 1:** 5·6장 공백 상태에서 `src/levels.js`, `src/sprites.js`, 렌더 코드, `index.html`을 만들려 하면 중단.
- **게이트 2:** 테스트 기대값이 2장 숫자로 역추적되지 않으면 그 테스트는 쓰지 않는다.
- **게이트 3:** 코드가 2장 숫자를 바꾸려 하면 기획서를 먼저 고치고 사람에게 보고.
- **게이트 4:** AGENTS.md 미명명 경로(`src/render.js`, 테스트 파일명)를 사람 결정 없이 신설하지 않는다.
- **게이트 5:** V-1..V-6 통과를 R1 goal 완료로 보고하지 않는다. 9장 없이는 완료 선언 금지.
