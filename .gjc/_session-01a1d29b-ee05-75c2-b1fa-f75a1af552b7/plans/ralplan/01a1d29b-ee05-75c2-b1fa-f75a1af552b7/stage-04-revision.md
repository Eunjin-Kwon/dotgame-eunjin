## 1. 확정된 사람 결정 (재질문 금지)

1. **2장 값 7개 확정:** 격자 한 칸 이동 / 한 칸 150 ms / 타일 32 px / 화면 512×384 px = 16×12 타일 / 방향키 4개, 대각선 없음 / 이동하려는 칸이 벽이거나 화면 밖이면 제자리 / 짧게 누르면 정확히 한 칸, 누르고 있으면 150 ms마다 한 칸, 한 칸 이동이 끝나기 전 입력은 무시.
2. **타이밍 의미 확정:** 입력 시점에 즉시 한 칸 이동하고, 그 후 150 ms 동안 다음 입력을 잠근다(쿨다운). 보간/트윈 없음.
3. **표기 변경은 후속 작업:** 2장의 "(에이전트 제안)"을 "(확정)"으로 바꾸는 GAME_DESIGN.md 편집은 ralplan 중 금지(계획 가드)다. ralplan 종료 후 `design-v1:` 커밋으로 수행해야 하며, **아직 수행되지 않았다.**
4. **착수 게이트 (문장 하나):** **design-v1 커밋 완료 → R1a 착수.** 2장 표기가 "(확정)"으로 커밋되기 전에는 R1a를 시작하지 않는다(AGENTS.md "기획서를 먼저 고친다").

## 2. Principles

1. **기획서가 유일한 근거.** 2장 7개 값과 확정된 타이밍 의미만 쓴다. 기획서에 없는 숫자(타이머, 점수, 이슬방울 개수 등)는 계획·코드·테스트에 넣지 않는다.
2. **빈 장은 채우지 않는다.** 4·5·6·9장은 비어 있다. 맵 문자, 레이아웃, 색 hex, 완료 기준을 계획이나 코드가 발명하지 않는다.
3. **완료 근거는 9장이다.** 계획이 쓰는 검증 항목(V-*)은 2장 계약 확인용이며 goal 완료 선언 근거가 아니다.
4. **로직은 순수, 데이터는 분리.** `src/logic.js`는 canvas/document/window를 모른다. 문자→통행 가능 변환은 `src/levels.js` 한 곳에만 둔다.
5. **테스트 기대값은 기획서 숫자에서만.** 2장에 없는 동작은 계획이 기본값으로 적고 **사람 확인 항목**으로 표기한다(§8-8). 시간은 인자로 주입해 가짜 시간으로 결정적으로 검증한다.

## 3. Decision Drivers (top 3)

1. **2장은 확정, 5·6·4·9장은 공백.** 확정된 계약만 코드로 닫을 수 있고, 맵·표현·완료 판정은 사람 입력 대기다.
2. **AGENTS.md 완료 조건이 9장을 지목한다.** 9장 공백이므로 어떤 코드 작업도 R1 goal을 공식적으로 닫지 못한다.
3. **AGENTS.md "기획서를 먼저 고친다"가 실행 순서를 고정한다.** 따라서 게이트는 design-v1 커밋 완료 하나다.

## 6. R1 작업 분해 (파일 단위, 기획서 장 연결)

### R1a — design-v1 커밋 완료 후 착수

| 파일 | 작업 | 근거 장 | 내용 |
|------|------|---------|------|
| `src/logic.js` (AGENTS.md 명명) | 생성 | 2장 | 순수 함수만. canvas/document/window 참조 금지. 단일 export: `requestMove(state, dir, nowMs, grid)` → 새 state. |

**`requestMove` 규칙**

- (a) `nowMs < state.lockedUntil`이면 입력을 무시하고 state를 그대로 반환 — 2장 "이동이 끝나기 전 입력은 무시".
- (b) `dir`은 `up`/`down`/`left`/`right` 4개만 유효하다. 그 밖의 값은 이동을 만들지 않는다 — 2장 "방향키 4개, 대각선 없음". 동시 입력·대각선 조합 규칙을 계획이 새로 만들지 않는다(dir은 한 번에 하나).
- (c) 대상 칸이 `0 <= x < grid.width`, `0 <= y < grid.height` 밖이거나 `grid.blocked(x, y)`가 true면 이동은 생기지 않는다 — 2장 "벽과 화면 밖이면 제자리".
- (c-1) **기본값 (CR2-01, 사람 확인 항목):** 입력이 이동을 만들지 않는 경우((b)의 무효 dir, (c)의 벽·화면 밖) **state 전체가 불변이며 `lockedUntil`도 갱신하지 않는다.** 이 규칙은 2장에 없는 **미확정 계획 기본값**이다. 사람이 달리 정하면 기획서 2장을 고치고 테스트를 다시 쓴다(§8-8).
- (d) 이동이 성립하면 x,y를 즉시 1칸 변경하고 `lockedUntil = nowMs + 150` — 2장 150 ms, 확정된 쿨다운 의미.

**반복 구동 소유 (CR2-03):** 2장 "계속 누르고 있으면 150 ms마다 한 칸"은 `requestMove` 단일 호출로 생기지 않는다. **반복 구동은 R1a 범위 밖이고 호출자(R1b 입력 루프)가 소유한다. 검증은 V-9 (6)에서만 한다.** 이를 위한 R1a 테스트는 신설하지 않는다.

| 파일 | 작업 | 근거 장 | 내용 |
|------|------|---------|------|
| 테스트 (`node --test test/`로 실행; 파일명은 §8-5 열린 결정) | 생성 | 2장 | 150 ms와 16×12를 파일 상단 상수 한 곳에 모으고 출처를 2장으로 주석. 케이스는 V-1..V-6과 1:1. |

**R1a fixture 규칙:** 시작 위치는 테스트 fixture 값이며 **레벨 데이터가 아니라고 주석에 명시한다.** 벽은 `blocked(x, y)` boolean 함수 또는 차단 좌표 Set으로만 표현하고, 벽 문자는 어디에도 쓰지 않으며 `src/levels.js`를 참조하지 않는다.

## 7. R1 검증 항목 (기획서 장 번호 대응)

> **중요:** 아래 항목은 **2장 이동 계약을 확인하는 검증 항목이며 goal 완료 기준이 아니다.** AGENTS.md는 완료 조건을 9장으로 정의하고 9장은 비어 있다. R1a가 V-1..V-6을 모두 통과해도 **R1 goal은 열린 상태**이다.

### R1a 검증 — `node --test test/`로 확인 가능 (2장 계약)

- **V-1 (2장: 격자 한 칸 단위)** `up`/`down`/`left`/`right` 각 1회 입력에 좌표가 정확히 1칸만 바뀐다.
- **V-2 (2장: 방향키 4개) — CR2-04 반영** `dir`이 `up`/`down`/`left`/`right` 이외의 값이면 좌표가 불변이다. (대각선·동시 입력 규칙을 새로 만들지 않는다.)
- **V-3 (2장: 화면 밖이면 제자리)** 16×12 그리드 경계(x=0, x=15, y=0, y=11)에서 밖으로 향한 입력은 좌표를 바꾸지 않는다.
- **V-4 (2장: 벽이면 제자리)** `grid.blocked(x, y)`가 true인 칸으로 향한 입력은 좌표를 바꾸지 않는다.
- **V-5 (2장: 150 ms, 이동 중 입력 무시)** 이동 직후 `lockedUntil`은 `nowMs + 150`이며, `nowMs < lockedUntil`인 입력은 무시되고, `nowMs >= lockedUntil`인 다음 입력은 1칸 이동을 만든다. 실제 대기 없이 `nowMs` 주입으로 검증한다.
- **V-6 (AGENTS.md: logic.js는 canvas를 모른다)** 테스트가 `src/logic.js` 파일을 텍스트로 읽어 `canvas`, `document`, `window` 토큰이 등장하지 않음을 assert한다.

> 반복 구동(2장 "계속 누르면 150 ms마다 한 칸")은 **R1a 검증 항목에 들어가지 않는다.** 소유는 호출자(R1b 입력 루프)이고 검증은 V-9 (6)이다 (CR2-03).
> (c-1) 미확정 기본값(이동이 없으면 state 전체 불변)은 V-3·V-4에서 `lockedUntil`이 불변인지 확인한다. 단, 사람 확인 전에는 비결정 항목이며, 사람이 다르게 정하면 이 두 테스트를 고친다 (§8-8).

### R1b 검증 — 조건부, 현재 차단 (R1a 결과에 포함하지 않는다)

- **V-7 (2장: 화면 512×384, 타일 32 px) — 5·6장 확정 후.** `index.html`을 브라우저로 직접 연다(서버 없음; 필요 시 `python3 -m http.server 8000`). canvas 요소의 `width`=512, `height`=384를 확인하고 화면이 16×12 타일 격자로 구성됨을 확인한다.
- **V-8 (5장: 레벨 1 맵) — 5장 확정 후 차단 해제.** 5장 문자 그림과 화면을 나란히 두고 벽 칸·빈 칸 배치가 문자 그림과 일치함을 확인한다.
- **V-9 (2장: 한 칸 이동 + 반복 구동) — 5·6장 확정 후.** 관찰 절차: (1) 반딧불이의 시작 칸 좌표를 격자 기준으로 적는다. (2) → 키를 한 번 짧게 누른다. (3) 반딧불이가 오른쪽으로 정확히 1칸(32 px) 이동한 뒤 멈춘다. (4) ←, ↑, ↓도 같은 방식으로 각 1회 확인한다. (5) 벽에 인접한 칸과 화면 가장자리 칸에서 벽/밖 방향 키를 누르면 칸이 바뀌지 않는다. (6) **판정 기준 (CR2-05): 키를 계속 누르고 있을 때 150 ms 잠금 해제 시점마다 정확히 1칸이 움직이고, 잠금 중에 들어온 입력은 무시된다(다중 이동 없음).** 이 항목이 반복 구동의 유일한 검증이다.
- **V-10 (6장: 8색 hex) — 6장 공백으로 현재 검증 불가 (차단).** 6장 8색이 확정되면 소스의 색 리터럴이 그 8개 집합 안에 있는지 확인한다.

## 8. Blockers / Open items (사람 결정 필요)

1. **5장 맵 — 비어 있음 (차단).** 문자 규칙과 레벨 1의 16×12 문자 그림이 없다. AGENTS.md는 5장 문자 규칙을 `src/levels.js`에 **그대로 복사**하라 하고 좌표 별도 기재를 금지한다. **따라서 R1의 맵 내용은 5장 없이 완성할 수 없다.**
2. **6장 팔레트 — 비어 있음 (차단).** 8색 hex가 없으면 팔레트 인덱스 의미와 렌더 색이 정의되지 않는다. 임시 색 금지.
3. **9장 수용 기준 — 비어 있음, R2 소관 (차단).** 9장 없이 **확인 가능한 것**: 2장 이동 계약 V-1..V-6을 `node --test test/`로 숫자 기반 검증. **확인 불가능한 것**: goal 완료 선언, 성공/실패 판정, 점수, 타이머, 레벨 전환. 계획은 임시 수용 기준을 만들어 완료 근거로 삼지 않는다.
4. **4장 오브젝트 — 비어 있음 (차단).** 반딧불이 스프라이트 모양·크기가 없어 R1b 렌더에 필요하다.
5. **파일 경로 — 열린 사람 결정.** AGENTS.md 명명 파일은 `src/logic.js`, `src/levels.js`, `src/sprites.js`, `src/strings.js`, `index.html`이고 명령은 `node --test test/`다. **렌더 코드 경로(`src/render.js` 신설 여부)와 테스트 파일명은 여전히 사람 결정 항목이다.** 계획은 이 두 경로를 확정으로 가정하지 않는다.
6. **타이머 — 기획서 미정의.** 제한 시간 숫자가 GAME_DESIGN.md 어디에도 없다. R1 범위 밖이며 필요해지면 사람이 기획서에 먼저 쓴다.
7. **2장 표기 변경 — 착수 게이트(미수행).** "(에이전트 제안)" → "(확정)"은 ralplan 계획 가드로 지금 수행할 수 없다. **design-v1 커밋 완료 → R1a 착수.**
8. **미확정 기본값 — 사람 확인 항목 (CR2-01).** "입력이 이동을 만들지 않으면 `lockedUntil` 포함 state 전체 불변"은 2장 숫자가 아니라 **계획이 제시하는 미확정 기본값**이다. 사람이 확인하거나 다르게 정해야 하고, 다르게 정하면 기획서 2장을 먼저 고치고 V-3·V-4를 다시 쓴다.
9. **동시 입력 선택 규칙 — 열린 사람 결정 (CR3-02).** dir은 호출당 하나이므로 여러 키가 동시에 눌린 경우 입력 루프가 어떤 dir을 넘길지는 사람이 정한다. 2장에 규칙이 없으므로 계획이 새로 만들지 않는다.

## 11. Verification Plan

- 명령: `node --test test/` (AGENTS.md 명령어 절). 다른 러너·플래그·의존성 추가 금지.
- 시간 검증: 실제 대기 없이 `nowMs` 인자 주입. 150 ms는 테스트 상단 상수 한 곳에 두고 출처를 2장으로 주석.
- 반복 구동: R1a 테스트로 검증하지 않는다. V-9 (6) 사람 관찰만이 근거다.
- 사람 확인: `index.html`을 브라우저로 직접 연다(서버 없음). 필요 시 `python3 -m http.server 8000`. R1b 차단 해제 후에만 유효.
- 증거 규칙: fixture 데이터로 찍은 스크린샷은 증거가 아니다. V-8/V-9 확인은 5장 맵으로 렌더한 화면이어야 한다.
- 보고 규칙: R1a 완료 보고 시 "2장 계약 V-1..V-6 통과, R1 goal 열림, 사람 브라우저 확인 미완, 9장 공백"을 함께 말한다.
- 규범 문장 대응 확인(CR3-01): V-1~V-6은 각각 §6 (a)~(d)와 §1의 확정 항목에 1:1로 대응한다. V-1↔(d)+2장 격자 한 칸, V-2↔(b), V-3↔(c) 경계, V-4↔(c) blocked, V-5↔(a)+(d) 150 ms, V-6↔AGENTS.md 순수성. (c-1) 기본값은 V-3·V-4의 `lockedUntil` 불변 확인으로 덮인다.

## 12. Escalation / Risk Gate

- **즉시 에스컬레이션:** 구현 중 4·5·6·9장 값을 추측하고 싶어지는 순간 멈추고 사람에게 묻는다. 같은 시도 6회 초과 금지(AGENTS.md).
- **게이트 1:** design-v1 커밋 전에는 R1a를 시작하지 않는다.
- **게이트 2:** 5·6장 공백 상태에서 `src/levels.js`, `src/sprites.js`, 렌더 코드, `index.html`을 만들려 하면 중단.
- **게이트 3:** 테스트 기대값이 2장 숫자 또는 사람 확인된 기본값(§8-8)으로 역추적되지 않으면 그 테스트는 쓰지 않는다.
- **게이트 4:** 코드가 2장 숫자를 바꾸려 하면 기획서를 먼저 고치고 사람에게 보고.
- **게이트 5:** V-1..V-6 통과를 R1 goal 완료로 보고하지 않는다. 9장 없이는 완료 선언 금지.
- **게이트 6:** 반복 구동을 R1a에 구현하지 않는다(CR2-03).
- **게이트 7:** 동시 입력 선택 규칙을 계획·코드가 임의로 정하지 않는다(§8-9).
